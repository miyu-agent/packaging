# Miyu packaging

> <sub>This document was generated by Anthropic's Claude Fable 5.2.</sub>

This repository holds the templates and workflows used to publish the Miyu family of programs to package repositories, for example the `PKGBUILD` for the AUR.

It is not the same thing as [miyu-agent/packages](https://github.com/miyu-agent/packages): `packages` is the index of Miyu packages, while this repository only publishes the programs themselves to system package repositories.

## Who does what

| What | Where |
|---|---|
| Archives for each platform, checksum files, build provenance attestations | Each program's own repository; its release process builds them and puts them on its GitHub releases page |
| Templates and workflows used when publishing to package repositories | This repository |

The secrets used for publishing are stored only in this repository's settings; the programs' source repositories do not hold them.

## What is here now

| Workflow | What it does | Secret |
|---|---|---|
| [`aur.yml`](.github/workflows/aur.yml) | Pushes one release of [LiteMiyu](https://github.com/miyu-agent/litemiyu) to the AUR (package name `litemiyu-bin`) | `AUR_SSH_PRIVATE_KEY` |
| [`npm.yml`](.github/workflows/npm.yml) | Publishes one release of LiteMiyu to npm (the main package under two names, `litemiyu` and `@miyu-agent/litemiyu`, plus three platform packages) | `NPM_TOKEN` |

Both workflows are triggered by hand and default to a dry run that pushes nothing. They work the same way:

1. Take the template from the program's repository, download the archives and checksum files from its releases page, and check the hashes and the build provenance attestation.
2. Fill in the template, then do a real install and one run in an environment that never touches the secrets.
3. Only when it is not a dry run, use the secret in a separate job that does nothing but push.

The templates live in the program's own repository (LiteMiyu's are in its `packaging/` directory) and change together with the program's version. The Homebrew formula is updated by the workflow of [miyu-agent/homebrew-tap](https://github.com/miyu-agent/homebrew-tap) itself, which needs no extra secret.

## Publishing a version

Taking `v2026.11.0` as the example:

```bash
# Dry run first
gh workflow run aur.yml -R miyu-agent/packaging -f tag=v2026.11.0
gh workflow run npm.yml -R miyu-agent/packaging -f tag=v2026.11.0

# Publish for real once the dry run passes
gh workflow run aur.yml -R miyu-agent/packaging -f tag=v2026.11.0 -f dry_run=false
gh workflow run npm.yml -R miyu-agent/packaging -f tag=v2026.11.0 -f dry_run=false
```

The release that the tag belongs to must already be public; a draft release cannot be downloaded.
